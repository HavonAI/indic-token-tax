# The Indic Token Tax

Code and results for two Havon AI papers (both forthcoming):

1. *The Indic Token Tax in 2026: Measuring Tokenizer Disparity and Its Cost for the Languages of India*
2. *A Multi-Word Tokenizer for 204 Languages That Needs Fewer Tokens Than GPT-4o's, Including on English* (Havon v3 and v4)

The scripts count how many tokens public LLM tokenizers need for the same content in English and in Indian languages. Everything is pinned: dataset checksums or revisions, tokenizer revisions and sampling seeds. Only tokenizer files are downloaded, never model weights, and no text in the study was generated by a language model.

## Reproduce

Python 3.12 or later. Run all commands from the repository root.

```bash
pip install -r requirements.txt
TOK=(--tokenizer "Havon v1=tokenizers/havon_v1/tokenizer.json" --tokenizer "Havon v2=tokenizers/havon_v2/tokenizer.json" --tokenizer "Havon v3=tokenizers/havon_v3/tokenizer.json")
python measure.py --mecorpus PATH/TO/me_roman.txt "${TOK[@]}"   # FLORES-200, PHINC, HingCorpus, MeCorpus
python morph_align.py "${TOK[@]}"                               # morpheme boundary alignment (MorphTok)
python cost.py                                                  # illustrative rupee cost example
python dakshina.py "${TOK[@]}"                                  # romanized vs native script (Dakshina)
python check_tokenizer_equivalence.py                           # DeepSeek V4 vs V3 tokenizer check
# Havon v3 (Section IV-H): all 204 FLORES-200 languages; FLORES tarball is downloaded by measure.py
python eval_world.py --flores data/flores/flores200_dataset.tar.gz --split devtest \
    --candidate "Havon v3=tokenizers/havon_v3/tokenizer.json" --candidate "Havon v2=tokenizers/havon_v2/tokenizer.json" --out results
```

### Havon v4 (multi-word tokenizer)

```bash
CANDS=(--candidate "v4-200k=tokenizers/havon_v4/tokenizer_200k.json" --candidate "v4-256k=tokenizers/havon_v4/tokenizer_256k.json" --candidate "v4-512k=tokenizers/havon_v4/tokenizer_512k.json")
python eval_world.py --flores data/flores/flores200_dataset.tar.gz --split devtest "${CANDS[@]}" --out results/v4/check
# Control at GPT-4o's vocabulary size: v3 cut to 200,019 tokens
python truncate.py tokenizers/havon_v3/tokenizer.json 200019 havon_v3_200k.json
python eval_world.py --flores data/flores/flores200_dataset.tar.gz --split devtest --candidate "v3-200k=havon_v3_200k.json" --out results/v4/check_v3
```

The token counts behind the v4 paper are in `results/v4/`: `v4_200k` (dev and devtest), `v4_256k_512k` (dev and devtest), `v3_200k` (devtest) and `v3_1_dev` (the rebalanced v3.1 ablation, dev only; its tokenizer is not released).

### Training the tokenizers

`training/` holds the scripts that trained v3 and v4. They stream public datasets from Hugging Face and need about 32 GB of RAM at full size; `--scale 0.001` runs a small local test.

```bash
cd training
python -m tokenizer_v3.train_v3 --out OUT --phase sample                     # per-language text samples
python -m tokenizer_v3.train_v3 --out OUT --phase train --samples OUT --fraction 0.6   # v3, 262,144 tokens
# v4 stage 2 needs the SuperBPE fork of tokenizers (https://github.com/alisawuffles/tokenizers-superbpe, commit 757f2a5, Python 3.12)
python -m tokenizer_v3.superbpe_stage2 --samples OUT --base OUT/havon_v3_256k.json --out V4 --inherit 210000 --vocab 524288 --fraction 0.12   # v4-256k and v4-512k
python -m tokenizer_v3.superbpe_stage2 --samples OUT --base OUT/havon_v3_256k.json --out V4_200K --inherit 160000 --vocab 200019 --fraction 0.12   # v4-200k
```

Per-language character budgets are in `training/tokenizer_v3/langs.py` and the data sources in `training/havonlm/sources.py`. Romanized Marathi needs `me_roman.txt` (see below) in the folder named by the `HAVON_RAW_DIR` environment variable.

Havon v3's vocabulary size (262,144) was chosen on FLORES-200 dev, using `truncate.py` to cut 65,536, 131,072 and 196,608-token versions from the same merge list (`results/world_dev.csv`); the paper reports devtest only (`results/world_devtest.csv`).

Outputs are written to `results/`. The committed files in `results/` are the outputs reported in the paper. Re-running should reproduce them byte for byte. The one exception is `summary.json`, which records the MeCorpus filename you pass in.

`me_roman.txt` is the romanized L3Cube MeCorpus. It is not redistributed here. Download it from the L3Cube MarathiNLP repository (https://github.com/l3cube-pune/MarathiNLP); `measure.py` records its SHA-256 so you can confirm you have the same file. Every other dataset and tokenizer is downloaded automatically.

## Contents

| Path | What |
|---|---|
| `measure.py` | Parity ratios with bootstrap confidence intervals, tokens per word, and characters per token, for all 25 FLORES-200 languages of India, PHINC, HingCorpus and MeCorpus |
| `morph_align.py` | Morpheme boundary precision, recall and F1 against MorphTok for Hindi and Marathi |
| `cost.py` | Worked example converting parity into list-price cost (illustrative, not measured) |
| `dakshina.py` | Romanized versus native-script tokens on Dakshina, for 12 languages |
| `check_tokenizer_equivalence.py` | Component-by-component SHA-256 comparison of the DeepSeek V3 and V4 tokenizers |
| `eval_world.py` | Token counts for every FLORES-200 language, for Havon v3 and the public rival tokenizers |
| `truncate.py` | Cuts a smaller BPE tokenizer from a larger one (exact prefix of its merges) |
| `results/` | Raw token counts and summaries behind every table and figure (`results/v4/` for the v4 paper) |
| `tokenizers/` | The Havon tokenizers (v1, v2, v3 and v4), with their training configuration |
| `training/` | Scripts that trained Havon v3 and v4 (`train_v3.py`, `superbpe_stage2.py`), with per-language budgets and data sources |
